# リスト/ランキングデータの再構成テクニック

一次情報源（公式アワードページ、ランキングサイトなど）がスクレイパーブロック・ペイウォールなどで `web_extract` 不可能な場合に、複数の `web_search` スニペットから完全なリストを再構成する手法。

## 適用場面

- アワード/ランキングの全エントリーリスト（ITエンジニア本大賞、ベストセラーランキング等）
- カンファレンスのスピーカー/セッション一覧
- プロダクトローンチラインナップ（同時発表された全製品・バージョン）
- 出版社の新刊一覧テーマ別まとめ
- 候補者リスト・ノミネート一覧

## 基本戦略

### 第一段: 複数ソースのスニペットを収集する

以下のような異なる種類のページを**同時に検索**して、それぞれが持つ部分情報を集める:

| ソース種別 | 特徴 | 典型ドメイン |
|-----------|------|-------------|
| 公式アナウンス/プレスリリース | 正式な全リストだがscraperで落ちやすい | prtimes.jp, shoeisha.co.jp |
| ニュース/メディア記事 | 上位N件のみ紹介だがscraperを通ることがある | publickey1.jp, itmedia.co.jp, codezine.jp |
| 書店/ECサイト | 全リストを持ちscraper耐性が高い | amazon.co.jp, yodobashi.com, e-hon.ne.jp |
| SNS/Facebook投稿 | リスト付き投稿が多い | facebook.com, x.com |
| 個人ブログ/nore | 読書レビュー形式で1冊ずつ紹介 | note.com |

### 第二段: 既知タイトルフラグメントを使った検索

部分的なリストが得られたら、未確認のエントリーを特定するために「既知のタイトル断片」を検索クエリに含める:

```text
# 既知の2-3タイトル + 期待される未確認キーワードで検索
"アワード名" "既知タイトル1" OR "既知タイトル2" "期待キーワード"
```

例（今回のセッション）:
```
"ITエンジニア本大賞2026" "技術書部門" "AIエージェント開発" "ことば" "科学的" "改訂" "100日" "MCP" "ゆるストイック"
```

これにより、検索エンジンが部分一致で未確認エントリーを含むページを返す。

### 第三段: クロスバリデーション

各エントリーが**2箇所以上の独立したソース**で確認できるまで検索を続ける:

1. 公式リリースのスニペット（最優先）
2. メディア記事のスニペット
3. ECサイトの商品ページ説明
4. SNS投稿

2箇所以上で一致したエントリーのみ確実と見なす。単一ソースのみのエントリーは「要検証」とマークする。

### 第四段: ギャップフィリング

検索を重ねてもリストの一部が欠ける場合、以下の手法で残りを特定する:

- **類推検索**: リストのテーマから「__と思われるキーワード」で検索
  - 例: 「アワード 技術書 2026 XX」→ 受賞書の出版社・著者で検索
- **site:制限検索**: 特定サイト内の言及を総ざらい
  - `site:yodobashi.com "ITエンジニア本大賞" 技術書`
- **逆引き検索**: リストの出版社がその分野で出している他のタイトルを調べる
  - 例: 「SBクリエイティブ AIエージェント 2026」

## 実践例: アワードリスト再構成の手順

1. **初回4並列検索** → 公式ページ・メディア記事・ECサイトのスニペットから暫定一覧を構築
2. **既知エントリーフラグメント検索**: 第一段で判明したエントリーの断片をクエリに含め、未確認エントリーを含むページを引き出す
3. **site:特定検索**: 完全リストを含む記事を特定（技術系・産業系メディアなど）
4. **ブラウザ取得**: 特定されたリストページを `browser_navigate` で直接取得し、全エントリー＋メタデータを確認
5. **クロスバリデーション**: ECサイト・SNS・プレスリリースで各エントリーを2重確認

## 注意点

- スニペットの切り詰め（`...`）に注意。完全な書名が省略されている場合、複数スニペットの断片を組み合わせて復元する
- ECサイトの「関連商品」や「この商品を買った人はこちらも購入」は正規のリストではないため、バリデーションには使わない
- リストの順序が「五十音順」「発売日順」「得票数順」なのかを確認する。ソースによって順序が異なる場合がある
- 年度が変わるとアワード名が同じでも対象期間や選出基準が変わる可能性がある
