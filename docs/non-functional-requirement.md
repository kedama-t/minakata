# 非機能要件

## 1. 可用性

- エージェントハーネスを利用する関係上、24時間稼働を原則とする
- (MVP)限られたチーム内での利用を想定しているため、稼働率は設定しない

## 2. 性能・拡張性

- WebUIについては、ノートパソコン、個人PC、廉価なVPSといった、リソースの少ない環境でもAPIのレスポンスは短く保つこと
- エージェントによる推論呼び出し回数が非常に多くなるため、フロンティアモデルではなく、ローカルLLM(Gemma 4など)、またはクラウドホスティングの安価なオープンウェイトモデル(DeepSeek V4 Flash)などを活用する
- バックエンドで編集・調査をするAIエージェントは複数稼働する可能性がある
- (MVP)個人〜少人数チームによる運用(1-10名)と、それよりも多いWeb閲覧ユーザー(-30名)を想定する

## 3. 運用・保守性

- エージェントハーネスを利用するため、AIの行動を追跡・閲覧できる仕組みを設ける
- (MVP)バックアップはドキュメントがテキストベースであることを利用し、GitHubで管理する
- (MVP)データベースについても、SQLiteを用いてファイルベースで管理することとする

## 4. 移行性

- (MVP)設定しない

##　5. セキュリティ

- 本プロダクトはAIエージェントハーネス、ひいてはLLMに強く依存したプロダクトであるため、**プロンプトインジェクションへの対策は厳重に施さなくてはならない**
- AIが危険な操作(外部からダウンロードしたシェルスクリプトの実行、プロジェクト外のファイル操作、秘匿情報の外部送信など)を実行できない仕組みを設けること
- (MVP)メールアドレスによる認証を行う。将来的にOktaなど認証基盤との統合が必要になる

## 6. システム環境・エコロジー

- (MVP)設定しない
